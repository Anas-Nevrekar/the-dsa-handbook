88. Merge_Sorted_Array
Difficulty: Easy
Here's an explanation of the C++ solution for merging two sorted arrays:

### 1. Problem Understanding
You're given two sorted arrays of integers, `nums1` and `nums2`. `nums1` has enough space to hold all elements from both arrays combined. Specifically, it contains `m` sorted elements followed by `n` empty slots (represented by zeros, but their value doesn't matter as they will be overwritten). `nums2` contains `n` sorted elements. The goal is to merge the elements from `nums2` into `nums1` such that `nums1` contains all `m + n` elements in non-decreasing order. This merge must happen in-place within `nums1`.

### 2. Approach
The core idea is to merge the arrays by working backwards from the end. Since `nums1` has sufficient empty space at its tail, we can place the largest elements from either `nums1`'s initial sorted portion or `nums2` into the largest available positions in `nums1` without overwriting elements that we still need to process. We maintain pointers (or rather, counters acting as effective pointers) for the end of `nums1`'s active data, the end of `nums2`, and the current position to fill in the final merged `nums1`. By comparing the largest remaining element from `nums1` and `nums2` at each step and placing the larger one, we ensure the final array is sorted.

### 3. Algorithm Steps
1.  Initialize a counter `k` to the total number of elements that will be in the merged array (`m + n`). This `k` will represent the count of elements yet to be placed, and `k-1` will be the index in `nums1` where the next element is placed.
2.  Loop while `k` (the count of elements to place) is greater than 0:
    *   **If `n` (the count of elements remaining in `nums2`) is 0:** This means all elements from `nums2` have already been placed into `nums1`. The remaining `m` elements of `nums1` are already in their correct sorted positions at the beginning of the array. So, we simply decrement `k` and continue, acknowledging these positions are correctly "filled".
    *   **Else if `m` (the count of elements remaining in `nums1`'s initial portion) is 0:** This means all elements from `nums1`'s original `m` elements have been processed. Copy the last remaining element from `nums2` (at index `n-1`) into `nums1` at index `k-1`. Then, decrement both `k` and `n`.
    *   **Otherwise (both `m` and `n` are greater than 0):** Compare the last remaining element of `nums1` (at index `m-1`) with the last remaining element of `nums2` (at index `n-1`).
        *   If `nums1[m-1]` is greater than or equal to `nums2[n-1]`: Copy `nums1[m-1]` to `nums1[k-1]`. Then, decrement both `k` and `m`.
        *   Else: Copy `nums2[n-1]` to `nums1[k-1]`. Then, decrement both `k` and `n`.

### 4. Time Complexity
The algorithm iterates through `m + n` elements exactly once. In each iteration, it performs a constant number of operations (comparisons, assignments, decrements). Therefore, the time complexity is **O(m + n)**.

### 5. Space Complexity
The solution modifies `nums1` in-place and uses only a few integer variables (`k`, `m`, `n`) to keep track of indices and counts. It does not create any new arrays or data structures proportional to the input size. Thus, the space complexity is **O(1)**.
